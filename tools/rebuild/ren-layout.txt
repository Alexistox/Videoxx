Naming rules
  - Folders: camelCase, by feature; a nested subfolder only for settings/project and editor/panels.
  - PascalCase.jsx for a file whose main export is a React component (e.g. editor/FacelessEditor.jsx, shell/Palette.jsx); small private subcomponents stay in the same file as their owner.
  - camelCase.js for non-component modules: hooks as useXxx.js (state/usePlan.js), helpers/data as noun names (lib/api.js, lib/format.js, script/scriptText.js, routines/nodes.js).
  - One original rollup module per file: keep each contiguous run together and never merge across a $N boundary. Drop rollup's $1/$2 suffixes (cache$1 -> cache, MentionField$1 -> refs/MentionField.jsx, while thumbnails/MentionField.jsx stays a separate file).
  - Icons: do not recreate the inlined lucide code (L15253-18193). Import from the `lucide-react` package and alias names that clash with app components (Image as ImageIcon, Library as LibraryIcon, Palette as PaletteIcon, Settings as SettingsIcon).
  - The `import.meta.url` asset constants become plain `import x from '../assets/...'`; `__vite_glob_0_*` becomes `import.meta.glob('../assets/figures/*.png', { eager: true, import: 'default' })`.
  - Turn `jsxRuntimeExports.jsx/jsxs(...)` back into JSX and `reactExports.useX` into `import { useX } from 'react'`.
